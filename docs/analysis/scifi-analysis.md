# 《MODALE / scifi》项目解析与设计方案分析

> 来源:https://beastydesign.github.io/scifi/ · 仓库 github.com/beastydesign/scifi(全权利保留，本报告仅作学习分析，复刻品为独立重写实现)
> 分析对象：一个以「科幻控制室 HUD」风格呈现越野赛事(留尼汪 Diagonale des Fous、UTMB)数据回放的纯静态站点。

---

## 1. 项目内容解析

### 1.1 它是什么

一个**单页数据可视化控制台**:把一场 180km 越野赛的官方轨迹、海拔、关门时间、历届成绩，重播在一个可交互的 3D 点云地形上。整体伪装成飞船/地面站的监控界面——这正是 "scifi" 的含义:**用科幻仪表语言包装真实数据**。

三个页面共用同一套引擎:`index.html`(Diagonale des Fous)、`utmb.html`(UTMB)、`blocky.html`(加密页面,需口令解锁)。

### 1.2 文件结构与分层

```
index.html / *.html     页面骨架:CSS Grid 布局 + 面板声明(纯语义化,无业务)
styles.css              设计令牌 + 组件样式(213 行,整个视觉系统的全部)
src/
  util.js               种子随机、稳定哈希、2D 梯度噪声(Perlin)、插值、数字分组
  gl.js                 WebGL2 最小内核:program/vao/fitCanvas/透视/lookAt/矩阵/投影
  chrome.js             页面"外框":跑马灯、UTC 时钟、图例、页脚、胶片颗粒
  hud.js                3D 视图故障艺术(glitch:slice/block/bar)
  race.js               赛事数据模型:加载、km-effort 插值、回放时钟、关门线
  race-panels.js        6 种 2D 仪表(环/剖面/坡度/累计/赛制/完赛)
  terrain.js            主视图:WebGL2 点云地形 + 等高线 + 轨迹 + 2D 标注层
  globe.js              点阵地球:Fibonacci 球 + 大圆弧线 + 旋转刻度环
  canvas2d.js           2D 面板公共件:surface/label/透明度分桶点
  unlock.js             加密页:PBKDF2+AES-GCM 口令解锁后动态装配页面
data/                   每场比赛一个 JSON + 两个二进制栅格(海拔 Int16、地表类型 Uint8)
```

**分工原则非常干净**:数据(纯 JSON/二进制)→ 模型(race.js)→ 视图(terrain/globe/panels)→ 装饰(chrome/hud)。视图不知道数据来源,装饰不知道业务含义。

### 1.3 数据模型

每场比赛的 `data/<race>.json` 是全部真相:

- `trace.points`: `[km, x, z, alt, dplus, dminus, lat, lon]` × 3349 点,官方 GPX 烘焙产物;
- `grid`/`land`: 海拔栅格(150m 格)与地表覆盖栅格(75m 格,ESA WorldCover ÷ 10);
- `checkpoints`: 含 `close`(关门时刻)的是"barrière horaire";
- `rivers`/`peaks`/`areas`: 烘焙期提取的河流(带流域面积)、山峰、区域名;
- `results`/`histogram`/`targets`: 历届前 10、完赛时间分布、目标区间;
- `display`: **全部视觉参数**(缩放单位、垂直 exaggeration、等高距、参考海拔、相机半径、标题文案、hub 坐标)——视觉与数据解耦的关键。

二进制栅格 + 索引式 JSON,无构建步骤,fetch 即用。

### 1.4 渲染技术

**主视图(terrain.js,全站最重的 635 行):**

- **24 万点 WebGL2 点云**:一次性生成,按地表类型上色(森林青绿、建成区琥珀……),顶点着色器里完成:
  - 伪景深(bokeh):按 `|depth - focus|` 计算弥散圆,大点渲染成**镜头光圈般的圆环**(`disc*0.22 + ring*1.5`),能量按面积守恒衰减;
  - 焦点周期性推拉(FOCUS_PERIOD=14s)、高度扫描线亮带(SCAN_PERIOD=11s)、每点闪烁 twinkle、距离雾;
  - `uReal` 单 uniform 在**黑白浮雕 ↔ 自然色彩**间渐变;
- **Marching squares 等高线**:在海拔栅格上逐格提取,线宽 alpha 分级(海岸线 0.55 > 整千米 0.42 > 主等高距 0.26 > 次等高距 0.1);
- **加色混合** `blendFunc(ONE, ONE)`——所有发光体直接相加,天然有"屏幕光"质感;
- **2D Canvas 标注层**叠在 WebGL 之上:轨迹(已跑琥珀实线+辉光/未跑白色虚线)、跑者脉冲标记、站点 pin(基座圆圈+杆+圆点)、**标签碰撞避让**(每帧维护已放置矩形,放不下就退化为只显示代码)、量尺、相机读数、glitch;
- 相机:方位/俯仰/半径轨道,拖拽/滚轮/双击复位,闲置 4s 后自动缓转。

**globe.js**:Fibonacci 均匀球面采样,按 Natural Earth 陆地位掩码过滤(海洋每 3 点取 1,陆地全留);大圆弧线用 slerp + 抬升,**脉冲头部沿弧奔跑**(`exp(-d*9)` 拖尾);叠加 2D 旋转刻度环与背面剔除的城市标注。

**race-panels.js(2D 仪表)** 的共同手法:**不用线,用点阵与短划**。海拔剖面是"点云+点簇下垂"(密度随高度),完赛分布是逐小时台阶点柱,赛制对比是 periodically 重新生长的虚线条。数字变化用 **scramble 字符翻滚** settle。

**chrome.js(活的界面)**:顶部跑马灯每 900ms 随机一条乱码指令并 scramble;页脚 16 个数字每 500ms 随机一个翻滚;UTC 时钟;每 2 帧平移一次随机颗粒 tile 的胶片颗粒层;body 上 1px/3px 的 CSS 扫描线。这些"无意义但持续活动"的装饰是控制室氛围的主要贡献者。

**hud.js glitch**:每隔 0.6–3s 爆发 1–4 个故障——slice(把已渲染 WebGL 帧的一条带横向错位 copy)、block(黑块+底部亮线)、bar(白色细线),存活 0.06–0.4s。

### 1.5 业务模型(race.js)

- 冠军分点成绩未公开 → 用 **km-effort**(km + D+/100)把最终时间均匀摊开,明确注释"是估计不是实测"——诚实的工程态度;
- 回放时钟:1 比赛小时 = 3.2s,循环 = 关门时间 + 4h 空档;
- 关门线在地图上是"随时间前进的可移动点",线性插值于相邻关门站点之间。

## 2. 设计方案与思路

### 2.1 核心设计命题

> **「把真实数据当作飞船遥测来对待」** —— 信息的可信度来自内容,氛围的可信度来自装饰,二者严格分层、互不污染。

### 2.2 视觉系统(六条支柱)

1. **单色画布 + 单一强调色**。`--bg #030304` 近黑、`--fg #e9e9e9`、中间只有三档白色透明度(dim 0.45 / faint 0.22 / line 0.13),唯一彩色是 `--amber #ff9a3c`。琥珀只给"关键状态":领先者已跑轨迹、关门线、警告日志。视线引导零成本。
2. **等宽字体 + 字距排版**。IBM Plex Mono Light 全局 10px,letter-spacing 0.04–0.32em;全部大写;标题靠**字距**而非字重获层级。tabular-nums 对齐数字列。
3. **面板即仪器**。每个面板:1px 弱边框 + 极淡纵向渐变 + **四角 9px 直角括弧**(CSS 伪元素)+ 字母角标(A–J)+ 右侧 7.5px 灰色小注。括弧是"可拆卸模块"的视觉暗示,也是科幻 UI 的符号锚点。
4. **网格布局即舱室结构**。`44px 顶栏 / 主体 / 18px 底栏`,`320px | 1fr | 340px` 三列,所有面板等高吸附网格,gap 统一 10px。顶栏下一条 140px 亮线段——一个几乎不可见的"品牌签名"。
5. **纹理层叠**:径向渐变底 → CSS 扫描线(`repeating-linear-gradient` 0.025 alpha)→ JS 动态颗粒(opacity 0.055, screen 混合)。三层叠加出"显示屏"质感,成本几乎为零。
6. **运动语言 = 仪表语言**:数字 scramble 翻转(420ms 内逐字符 settle)、日志打字机(12ms/字符 + 光标)、相机缓慢自动巡航、扫描线周期扫过、焦点呼吸。所有动画都是"机器在干活",没有一条纯装饰动画。

### 2.3 工程思路

- **零依赖、零构建**:原生 ES Modules + WebGL2 + Canvas2D,GitHub Pages 直接托管。2.5k 行 JS 手写矩阵,只为消灭依赖。
- **一次烘焙,处处插值**:重型工作(GPX 重采样、等高线所需的栅格、河流追踪、陆地掩码)离线烘成二进制/JSON,运行时只做插值与绘制。
- **双 Canvas 叠加模式**:WebGL 负责"物",2D Canvas 负责"字"(标注/读数/glitch 需要 DOM 无法做到的帧级绘制)。每层各自 `fitCanvas` 对齐 DPR。
- **性能手法**:点云静态上传一次;2D  thousands 点用**透明度分桶**(每档一次 fill);颗粒只在偶数帧重绘;所有 setInterval 装饰与 rAF 主循环分离。
- **防御与诚实**:WebGL 不可用会怎样?没有——它假设现代浏览器,并相信它。估计数据明确标注"estimation, pas un relevé"。

### 2.4 值得抄的模式(按可迁移性排序)

| # | 模式 | 迁移到任何数据大屏 |
|---|------|------------------|
| 1 | 设计令牌集中在 `:root`,强调色只标记状态 | 直接抄 |
| 2 | 面板四角括弧 + 字母角标 | 直接抄,纯 CSS |
| 3 | scramble 数字/跑马灯/颗粒/扫描线四件套 | 直接抄,~100 行 |

### 2.5 风险与注意

- 许可证为**全权利保留**:代码与设计不可直接复用,学习后需独立实现(本工作区的复刻框架即独立重写,仅借鉴设计模式)。
- WebGL2 是硬依赖;移动断点(1100px/560px)只做布局降级,3D 性能靠点数硬扛。
- 面板在窄屏的密度损失未补偿(等高线图例会被裁)。

## 3. 复刻与框架化方案(见 hud-framework/)

把上述系统抽象为 **HUD 控制台框架**:

- **布局与视觉层**:固定的控制室网格 + 面板/括弧/跑马灯/颗粒等全部做成 CSS 变量驱动;
- **主题层**:一个主题 = 一个 JS 配置对象(强调色、背景色相、品牌文案、跑马灯词表、KPI 定义、日志模板、地球 hub 坐标、地形配色、数据种子)。切换主题 = 换配置 + 改 `data-theme`;
- **数据层**:`synth.js` 用种子噪声程序化生成与原版同构的数据模型(海拔栅格、地表分类、河流、轨迹、站点、成绩、直方图),无烘焙资产也能跑;
- **引擎层**:glkit / terrain3d / globe / panels2d / chrome 五个模块,与主题、数据完全解耦。
